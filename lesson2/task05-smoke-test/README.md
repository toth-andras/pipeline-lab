# Задание 5. Smoke-тест в пайплайне

**Что делаем:** проверяем, что собранный образ не просто существует,
а реально запускается и отвечает. Сканер уязвимостей этого не
проверяет.

## Что сделать

Добавьте в workflow третью джобу `smoke`, которая:

1. Зависит от джобы с пушем образа (`needs`).
2. Логинится в GHCR и скачивает **только что запушенный** образ
   (тег — хэш коммита).
3. Запускает контейнер: `docker run -d -p 8000:8000`.
4. Ждёт старта и проверяет `curl http://localhost:8000/health` —
   с повторными попытками (приложению нужно пара секунд).
5. Дополнительно проверяет, что ответ `/` содержит ожидаемую версию
   (grep по хэшу коммита или версии тега — смотря что у вас теперь
   в `APP_VERSION`).
6. Падает, если проверка не прошла. Падает сама по себе — не
   заканчивайте шаг `|| true`.

## Критерий приёмки

- Зелёный прогон, в логе джобы виден JSON от `/health`.
- Проверка честная: временно сломайте приложение (например,
  верните из `/health` статус `500`), убедитесь, что джоба падает,
  верните как было. Скриншот красного прогона — тоже в отчёт.

## В отчёт

- фрагмент workflow с джобой `smoke`;
- скриншот упавшего прогона со сломанным health-эндпоинтом
  и финального зелёного.
