# Задание 2. Версия из git-тега

**Что делаем:** учим пайплайн реагировать на релизные теги.
Пуш тега `v1.2.3` должен давать образ с тегами `1.2.3` и `latest`.

## Что сделать

1. Workflow должен запускаться и по тегам: добавьте в `on.push`
   секцию `tags`. Маска — `v*` (ВПИШИТЕ её сами).
2. Подключите `docker/metadata-action@v5` — он сам собирает список
   тегов образа. Нужны правила:
   - тег `sha-<хэш>` на каждый коммит (тип `sha`);
   - семвер из git-тега (тип `semver`, шаблон `{{version}}`);
   - `latest` — только для ветки main (тип `raw` с условием `enable`).
3. Уберите ручной `docker tag`/`docker push` из шага Push, если он
   мешает — теги теперь приходят из metadata-action (его output
   `tags` принимает и build-push-action, и ваш ручной push).
4. Обратите внимание: build-arg `APP_VERSION` тоже должен стать
   человеческим — передайте туда версию релиза, когда прогон
   идёт по тегу (подсказка: `github.ref_name`).

## Проверка

```bash
git tag v0.1.0
git push origin v0.1.0
```

В GHCR у пакета должны появиться теги `0.1.0` и `latest`.
Скачайте образ через Artifactory и убедитесь, что `/` отвечает
версией `0.1.0`.
