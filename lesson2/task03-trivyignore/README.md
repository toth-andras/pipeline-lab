# Задание 3. HIGH-находки и осознанный .trivyignore

**Что делаем:** на занятии 1 мы смотрели только CRITICAL. Теперь
поднимаем планку до HIGH и учимся жить с тем, что сканер находит
всегда.

## Шаг 1. Верните HIGH в сканирование

В шаге Trivy замените:

```yaml
severity: CRITICAL
```

на `CRITICAL,____` (впишите второй уровень сами). Пушим — пайплайн
падает: на свежем `python:3.12-slim` находок всё равно десятки.
Откройте лог и посмотрите на колонку **Status** у находок.

**Вопрос (письменно):** что общего у большинства этих находок
и почему «починить их все» прямо сейчас невозможно?

## Шаг 2. ignore-unfixed

Добавьте в шаг Trivy параметр, который отфильтровывает находки
без доступного исправления (точное имя ищите в документации
aquasecurity/trivy-action). Пушим.

**Что должно получиться:** из десятков находок остаётся буквально
одна-две — те, на которые фикс уже существует, но базовый образ его
ещё не подхватил. Выпишите: CVE, пакет, версия фикса.

## Шаг 3. Разбираемся с оставшейся находкой

Два пути — выберите и обоснуйте:

1. **Починить**: обновить пакет в Dockerfile (`apt-get upgrade`
   для конкретного пакета). Плюсы/минусы?
2. **Подавить**: взять `templates/.trivyignore`, положить в корень
   репозитория, вписать CVE **с комментарием** — почему подавляем
   и когда пересмотрим. Подключить файл в шаге Trivy параметром
   `trivyignores`.

## Критерий приёмки

Прогон зелёный при `severity: CRITICAL,HIGH`. В репозитории —
либо починка в Dockerfile, либо `.trivyignore` с осмысленным
комментарием. Подавить «чтобы было зелёно» без обоснования —
не принимается.
