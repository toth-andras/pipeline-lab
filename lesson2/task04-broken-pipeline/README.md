# Задание 4. Почините сломанный пайплайн

**Что делаем:** учимся читать чужие ошибки. В файле
`templates/ci-broken.yml` — workflow с **тремя** спрятанными
ошибками. Это типичный «наследованный» пайплайн от уволившегося
коллеги.

## Что сделать

1. Положите файл в `.github/workflows/broken.yml` и запушьте.
2. Workflow упадёт. Найдите первую ошибку, исправьте, запушьте —
   проявится следующая. Ошибки расставлены так, что чинить их
   придётся по очереди, и логи Actions — ваш главный инструмент.
3. Доведите workflow до полностью зелёного состояния (джобы
   `lint-test` и `docker`, образ запушен в GHCR).
4. Когда почините — **удалите** `broken.yml` из репозитория, чтобы
   он не дублировал основной пайплайн, и запушьте удаление.

## Подсказки (смотреть только если застряли на 10+ минут)

- Первая ошибка видна ещё до запуска — GitHub покажет её красным
  в списке workflow, джобы не появятся вовсе.
- Вторая вылезет в шаге сборки образа. Внимательно прочитайте
  сообщение docker об имени образа.
- Третья — в самом конце, на пуше. Вспомните занятие 1: что обязательно
  идёт перед `docker push`?

## В отчёт

Три строки: какая была ошибка → как исправили. Плюс скриншот
итогового зелёного прогона.
